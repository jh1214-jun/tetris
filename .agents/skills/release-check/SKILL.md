# release-check

## 진행 원칙

- 프로젝트 루트의 PRD.md와 README.md, 현재 구현 및 기존 테스트를 읽고 요청된 단계만 점검한다. HTML/CSS/JavaScript와 직접 파일 실행을 전제로 하며 프레임워크나 빌드 도구를 요구하지 않는다.
- 코드를 직접 수정하지 않는다. 기존 테스트, 읽기 전용 확인, 임시 재현 환경으로 증거를 수집한다.
- 각 항목의 판정과 파일·위치, 실행 명령·결과 또는 재현 절차를 기록한다. 아직 구현하지 않은 후속 기능은 해당 없음, 도구·접근 부족으로 확인하지 못한 항목은 미검증으로 적고 통과로 간주하지 않는다.
- 높은 심각도는 실행 불가·상태 손상·핵심 시나리오 차단, 중간은 일부 조건의 기능 오류·유지보수 방해, 낮음은 기능을 막지 않는 가독성·표현 문제로 분류한다.

## 점검 체크리스트

- [ ] 파일 연결 — 통과: index.html에서 CSS와 JavaScript 및 필요한 자산을 올바른 상대 경로로 참조한다; 실패: 누락 파일, 대소문자 불일치 또는 로컬 절대 경로가 있다.
- [ ] 직접 실행 — 통과: index.html을 더블클릭해 서버·설치·빌드 없이 동작한다; 실패: 모듈 import, fetch 또는 개발 서버에 의존해 file URL에서 실패한다.
- [ ] 실행 안내 — 통과: README에 직접 여는 방법, 조작키, 테스트 명령과 실제 검증 결과를 적는다; 실패: 실행 불가능한 명령이나 현재 구현과 다른 설명이 있다.
- [ ] Pages 소스 — 통과: 저장소의 Pages 배포 방식과 소스 브랜치·폴더 또는 워크플로 산출물이 실제 정적 파일 위치와 일치한다; 실패: 확인한 설정이 파일 위치와 맞지 않는다.
- [ ] 프로젝트 하위 경로 — 통과: 저장소명 하위 URL에서도 상대 경로로 CSS·JavaScript를 로드한다; 실패: 루트 절대 경로 때문에 자산이 404가 된다.
- [ ] 배포 결과 — 통과: 제공된 배포 URL에서 자산 로드와 주요 플레이·재시작 흐름이 정상이다; 실패: 404, 콘솔 오류 또는 게임 동작 실패가 있다.

## 보고 형식

각 체크리스트 항목의 판정과 근거를 요약한 뒤 발견한 문제를 다음 표에 심각도 순으로 보고한다. 항목에는 파일·위치와 재현 조건 또는 확인한 증거를 포함한다. 개선안은 실행 가능한 최소 조치로 적는다. 문제가 없으면 발견한 문제 없음이라고 적고 빈 예시 행을 만들지 않는다. 미검증 사항과 남은 검증 방법을 별도로 명시한다.

| 항목 | 심각도(높음 · 중간 · 낮음) | 개선안 |
|---|---|---|

GitHub Pages 설정은 접근 가능한 저장소 설정이나 워크플로에서 읽기 전용으로 확인한다. 설정 또는 배포 URL에 접근할 수 없으면 미검증으로 보고한다. 이 스킬 호출만으로 커밋·푸시·배포·저장소 설정 변경을 수행하지 않는다.
