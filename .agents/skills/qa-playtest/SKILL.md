# qa-playtest

## 진행 원칙

- 프로젝트 루트의 PRD.md와 README.md, 현재 구현 및 기존 테스트를 읽고 요청된 단계만 점검한다. HTML/CSS/JavaScript와 직접 파일 실행을 전제로 하며 프레임워크나 빌드 도구를 요구하지 않는다.
- 코드를 직접 수정하지 않는다. 기존 테스트, 읽기 전용 확인, 임시 재현 환경으로 증거를 수집한다.
- 각 항목의 판정과 파일·위치, 실행 명령·결과 또는 재현 절차를 기록한다. 아직 구현하지 않은 후속 기능은 해당 없음, 도구·접근 부족으로 확인하지 못한 항목은 미검증으로 적고 통과로 간주하지 않는다.
- 높은 심각도는 실행 불가·상태 손상·핵심 시나리오 차단, 중간은 일부 조건의 기능 오류·유지보수 방해, 낮음은 기능을 막지 않는 가독성·표현 문제로 분류한다.

## 점검 체크리스트

- [ ] 첫 실행 — 통과: 직접 연 페이지에 10×20 보드, 점수 0, 활성 블록이 표시되고 자동 하강한다; 실패: 초기 상태가 다르거나 실행 오류가 난다.
- [ ] 이동·회전 — 통과: ←/→/↑ 입력이 즉시 반영되고 벽·고정 블록을 통과하지 않는다; 실패: 조작이 무시되거나 잘못된 위치를 허용한다.
- [ ] Soft Drop·고정 — 통과: ↓ 입력마다 한 칸 하강하고 막히면 정확히 고정한다; 실패: 여러 칸 이동, 겹침 또는 중복 고정이 생긴다.
- [ ] 라인과 점수 — 통과: 통제된 보드에서 1/2/3/4줄 제거가 각각 100/300/500/800점을 더하고 보드는 20행을 유지한다; 실패: 제거 수, 누적 점수 또는 보드 높이가 다르다.
- [ ] Game Over — 통과: 생성 위치가 막히면 종료 안내를 표시하고 시간·키 입력에 상태가 변하지 않는다; 실패: 종료를 놓치거나 종료 후 게임이 진행된다.
- [ ] Restart — 통과: 진행 중과 종료 후 재시작하면 빈 보드·점수 0·새 블록으로 돌아오고 반복해도 하강 속도가 같다; 실패: 이전 상태가 남거나 루프가 중복된다.
- [ ] 데스크톱 표시 — 통과: Chrome과 Edge에서 보드와 점수를 볼 수 있고 조작 키가 페이지를 스크롤하지 않는다; 실패: 화면이 가려지거나 조작 시 스크롤된다.

## 보고 형식

각 체크리스트 항목의 판정과 근거를 요약한 뒤 발견한 문제를 다음 표에 심각도 순으로 보고한다. 항목에는 파일·위치와 재현 조건 또는 확인한 증거를 포함한다. 개선안은 실행 가능한 최소 조치로 적는다. 문제가 없으면 발견한 문제 없음이라고 적고 빈 예시 행을 만들지 않는다. 미검증 사항과 남은 검증 방법을 별도로 명시한다.

| 항목 | 심각도(높음 · 중간 · 낮음) | 개선안 |
|---|---|---|

재현용 보드와 난수·시간 제어는 기존 테스트나 임시 환경에서 사용하며 배포 코드에 테스트용 상태나 조작 기능을 추가하지 않는다. 각 시나리오에 시작 상태, 입력 순서, 기대 결과, 실제 결과를 기록한다.
