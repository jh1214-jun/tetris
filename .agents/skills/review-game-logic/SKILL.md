# review-game-logic

## 진행 원칙

- 프로젝트 루트의 PRD.md와 README.md, 현재 구현 및 기존 테스트를 읽고 요청된 단계만 점검한다. HTML/CSS/JavaScript와 직접 파일 실행을 전제로 하며 프레임워크나 빌드 도구를 요구하지 않는다.
- 코드를 직접 수정하지 않는다. 기존 테스트, 읽기 전용 확인, 임시 재현 환경으로 증거를 수집한다.
- 각 항목의 판정과 파일·위치, 실행 명령·결과 또는 재현 절차를 기록한다. 아직 구현하지 않은 후속 기능은 해당 없음, 도구·접근 부족으로 확인하지 못한 항목은 미검증으로 적고 통과로 간주하지 않는다.
- 높은 심각도는 실행 불가·상태 손상·핵심 시나리오 차단, 중간은 일부 조건의 기능 오류·유지보수 방해, 낮음은 기능을 막지 않는 가독성·표현 문제로 분류한다.

## 점검 체크리스트

- [ ] 좌우·바닥 경계 — 통과: 모든 채워진 블록 칸에 대해 0~9열과 0~19행 범위를 검사한다; 실패: 행렬의 빈 칸으로 충돌을 판정하거나 경계를 벗어난 칸을 허용한다.
- [ ] 상단 처리 — 통과: 생성 규칙과 상단 경계 정책이 일치하고 음수 행을 배열 접근하지 않는다; 실패: 상단에서 예외가 발생하거나 블록이 사라진다.
- [ ] 고정 블록 충돌 — 통과: 채워진 칸끼리 겹치면 이동·회전을 거부한다; 실패: 블록이 통과하거나 기존 블록을 덮어쓴다.
- [ ] 회전 — 통과: 7종이 네 번 회전 후 복원되고 O 모양은 유지되며 원본 데이터는 불변이다; 실패: 칸 수가 바뀌거나 원본이 변형된다.
- [ ] 실패 동작 취소 — 통과: 벽·바닥·블록에 막힌 이동과 회전 후 상태가 유지된다; 실패: 실패한 시도에서 좌표나 모양이 일부 변경된다.
- [ ] 고정과 후속 처리 — 통과: 하강 실패 시 한 번만 고정하고 라인 제거 후 점수 갱신과 새 블록 생성·종료 판정을 수행한다; 실패: 중복 고정, 순서 오류 또는 생성 위치 겹침을 놓친다.

## 보고 형식

각 체크리스트 항목의 판정과 근거를 요약한 뒤 발견한 문제를 다음 표에 심각도 순으로 보고한다. 항목에는 파일·위치와 재현 조건 또는 확인한 증거를 포함한다. 개선안은 실행 가능한 최소 조치로 적는다. 문제가 없으면 발견한 문제 없음이라고 적고 빈 예시 행을 만들지 않는다. 미검증 사항과 남은 검증 방법을 별도로 명시한다.
