# bug-hunt

## 진행 원칙

- 프로젝트 루트의 PRD.md와 README.md, 현재 구현 및 기존 테스트를 읽고 요청된 단계만 점검한다. HTML/CSS/JavaScript와 직접 파일 실행을 전제로 하며 프레임워크나 빌드 도구를 요구하지 않는다.
- 코드를 직접 수정하지 않는다. 기존 테스트, 읽기 전용 확인, 임시 재현 환경으로 증거를 수집한다.
- 각 항목의 판정과 파일·위치, 실행 명령·결과 또는 재현 절차를 기록한다. 아직 구현하지 않은 후속 기능은 해당 없음, 도구·접근 부족으로 확인하지 못한 항목은 미검증으로 적고 통과로 간주하지 않는다.
- 높은 심각도는 실행 불가·상태 손상·핵심 시나리오 차단, 중간은 일부 조건의 기능 오류·유지보수 방해, 낮음은 기능을 막지 않는 가독성·표현 문제로 분류한다.

## 점검 체크리스트

- [ ] 루프·리스너 중복 — 통과: 반복 Restart 후 루프 하나와 단일 입력 처리가 유지된다; 실패: 하강이 빨라지거나 한 입력이 여러 번 실행된다.
- [ ] 상태 공유 — 통과: 보드 행, 블록 원본, 초기 상태가 독립적이다; 실패: 한 칸이나 블록 수정이 다른 행·블록·다음 게임을 오염시킨다.
- [ ] 경계와 배열 접근 — 통과: 상단·좌우 끝·바닥의 이동과 회전에서 예외나 범위 밖 기록이 없다; 실패: 잘못된 인덱스 접근, 블록 소실 또는 충돌 누락이 있다.
- [ ] 연속 라인 제거 — 통과: 인접하거나 떨어진 여러 완성 줄을 모두 제거하고 정확히 한 번 점수를 갱신한다; 실패: 행을 건너뛰거나 점수가 중복된다.
- [ ] 시간·입력 경합 — 통과: 자동 하강 직전·직후 Soft Drop과 Restart를 실행해도 고정·생성·초기화가 중복되지 않는다; 실패: 같은 블록을 두 번 고정하거나 이전 루프가 새 상태를 갱신한다.
- [ ] 종료 상태 — 통과: 종료 후 입력·타이머가 정지하고 Restart만 새 게임을 시작한다; 실패: 종료 후 점수나 보드가 변한다.
- [ ] 우선순위 — 통과: 재현 근거와 영향에 따라 상태 손상·실행 불가를 먼저 보고한다; 실패: 추측을 확정 버그로 쓰거나 재현 가능한 고위험 문제보다 미관 문제를 우선한다.

## 보고 형식

각 체크리스트 항목의 판정과 근거를 요약한 뒤 발견한 문제를 다음 표에 심각도 순으로 보고한다. 항목에는 파일·위치와 재현 조건 또는 확인한 증거를 포함한다. 개선안은 실행 가능한 최소 조치로 적는다. 문제가 없으면 발견한 문제 없음이라고 적고 빈 예시 행을 만들지 않는다. 미검증 사항과 남은 검증 방법을 별도로 명시한다.
